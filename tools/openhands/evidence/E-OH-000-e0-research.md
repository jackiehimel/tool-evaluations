# E-OH-000 — Phase E0 research report (read-only subagent, 2026-09-03; five citations spot-checked by the session against the public repos on 2026-09-04)

Scope note. The automation server is a fifth repo, `github.com/OpenHands/automation` (MIT, `pyproject.toml` name `openhands-automation` 1.10.0); the CLI is `github.com/OpenHands/openhands-cli` (MIT, 1.16.0). Source: docs.openhands.dev/openhands/usage/agent-canvas/architecture.md (Core Components).

1. Webhook events. The OSS automation server accepts cron schedules and inbound events: `POST /v1/events/{org_id}/{source}` (`openhands/automation/event_router.py` L4, L74; spot-checked). The GitHub schema covers `pull_request.*`, `pull_request_review.*`, `issues.*`, `issue_comment.*`, `push`, `release`, `workflow_run`, `check_run`; `check_suite` is absent (`event_schemas/github.py`; spot-checked: 0 occurrences). Caveat: built-in GitHub events are documented as forwarded from the OpenHands server (the Cloud/Enterprise GitHub App); custom sources registered via `POST /v1/webhooks` receive raw payloads (`webhook_router.py` L43, L98). The feature matrix row "Event-driven automations" reads "— | ✓ VM must be reachable | ✓ | ✓" across Local Backend, VM Backend, Cloud, Enterprise, while "Scheduled automations" and "Polling automations" are ✓ in all four (docs.openhands.dev/enterprise/enterprise-vs-oss.md, "Automations & Backend Features", fetched by the session 2026-09-04; docs.openhands.dev/openhands/usage/automations/event-automations.md). Whether the local launcher wires `AUTOMATION_WEBHOOK_SECRET` for the builtin GitHub source: not verified.
2. Push and PR. No dedicated git or PR tool in `openhands-tools` (packages: terminal, file_editor, browser_use, task_tracker, planning_file_editor, delegate, task); the agent uses the terminal with `git`/`gh` or the GitHub MCP server under `GITHUB_PERSONAL_ACCESS_TOKEN`. The `github-issue-to-pr` skill commits, pushes and opens the PR and needs Contents write (`extensions/skills/github-issue-to-pr/SKILL.md` L33, L60-62). Identity is a system-prompt instruction, not enforced config: use existing credentials and add a `Co-authored-by: openhands <openhands@all-hands.dev>` trailer, else `user.name=openhands` (`software-agent-sdk/openhands-sdk/openhands/sdk/context/prompts/sections/static.py` L186).
3. Headless start. CLI `openhands --headless -t "task"` (or `-f task.txt`, `--json`), always auto-approve; SDK `Conversation(agent=agent, workspace=cwd).send_message(...).run()`; automation server `POST /v1/preset/prompt`. (docs …/cli/headless.md; …/cli/command-reference.md L20-26; …/sdk/guides/hello-world.md L117-120; `extensions/automations/README.md`.)
4. Cost and tokens. Per automation run: Activity Log shows LLM cost in USD; export has a `cost` field; server column `AutomationRun.cost` (`automation/openhands/automation/models.py` L189-192; migration `013_add_run_cost.py`). Tokens per conversation in the Canvas metrics modal and the SDK `llm.metrics` (docs …/agent-canvas/managing-automations.md L34-38; …/sdk/guides/metrics.md).
5. PR Review Assistant. Posts a real pull-request review via `POST /repos/{repo}/pulls/{n}/reviews` with `event: COMMENT` always; the APPROVED / CHANGES REQUESTED verdict is body text (`extensions/skills/github-pr-reviewer/scripts/main.py` L821-831; spot-checked). Trigger: cron polling for a label, default every 15 min (`extensions/automations/catalog/github-pr-reviewer/manifest.json`). Nothing in the OSS product reacts on its own to a submitted review or a failing check; the repo-monitor template is cron-based and can be asked to watch failed workflow runs (docs …/agent-canvas/prebuilt/github-repo-monitor.md).
